ELI5 · 给完全不懂的人

每一维数一次人头，
加起来就是分数

HBOS（Histogram-based Outlier Score，基于直方图的异常分）。它大概是所有异常检测里最快的一个：不量任何两点之间的距离，只把每一维切成一排格子、数人头。这篇用大白话和两个能动手的演示讲清它 —— 也包括它最著名的那个盲区。

一句话先说清

把每一维切成格子，哪个格子人少，落进去就越可疑；
多维就把各维的可疑直接相加。

名字里的 Histogram 就是它的全部秘密：一维直方图。它从不问「你离别人多远」，只问「你所在的格子挤不挤」。所以它快得离谱 —— 也瞎得离谱，这两件事我们下面都会讲。

挤的格子

「这一档人很多」

落在这里，说明「这样的值很常见」，一点都不可疑。

空的格子

「这一档没什么人」

落在这里，说明「这么极端的值稀有」，第一个被叫出来。

记住这个画面：HBOS 眼里没有「邻居」，只有「格子」。这也是它和 KNN / LOF / COF 那一整族的根本区别 —— 那些人全都要量距离。
1

先说好处：它为什么能快成这样

老办法要算 n² 次距离；HBOS 只把每个数丢进格子，扫一遍就完事。

KNN、LOF、COF 的第一步都是「谁离谁多远」。n 个点要两两比一遍：220 个点是 2.4 万对，2 万个点是 2 亿对 —— 到这儿就没法算了。HBOS 反过来：每个点、每一维，只需要两次比较（找它在哪个格子、读出那个格子的密度），复杂度是 O(n·d)。

同样 12 个点：左边是 66 条线，右边是 4 个格子；点再多，右边的办法也只多扫几次

工程上怎么用：它常被当成第一道粗筛 —— 先用 HBOS 把 99% 明显正常的数据刷掉（便宜），剩下的再交给 LOF / 集成模型细看（贵）。这也是它在工业界口碑不错的原因。
2

第 1 步：一维数人头

把这一维切成 N 个等宽格子，数每格有多少点，
再换算成密度 ρ。

密度 = 该格点数 ÷（总点数 × 格宽）。乘上格宽是为了让所有柱子的面积加起来等于 1 —— 这样格子切粗切细，ρ 的量纲不变，可以直接比。规则只有一条：ρ 越小，分数越高。

单维得分
=
−log₂( ρ + α )

ρ 是该点所在格子的密度；α 是防止 log(0) 的小稳定剂，PyOD 默认 α = 0.1

为什么偏偏是 −log？两个理由

理由一

「越稀有越可疑」要有个尺度

ρ 从 0.5 掉到 0.05 是「稀有 10 倍」。−log₂ 把它翻译成「多了 3.3 分」，正好可以用加法讨论「稀有 10 倍 + 稀有 10 倍」。

理由二

相乘变相加

多维时（下一节）密度本来要连乘；取 log 之后变成相加。相加就能一眼看出「这次是 x 维拉高的分，还是 y 维」。

α 的代价：格子空着时 ρ = 0，单维得分封顶在 −log₂(0.1) = 3.32。也就是说所有空格子在 HBOS 眼里「一样空」—— 一个点落在两团之间的真空地带，和一个点落在天边，分数完全相同。这不是 bug，是它刻意选的简单。

3

第 2 步：多维就把分数加起来

二维怎么办？假设各维互不相干，
密度相乘 → 取 log → 分数相加。

如果两维独立，联合密度就等于两个边缘密度相乘：ρ(x,y) = ρ(x)·ρ(y)。取 −log 之后，乘法变成加法，于是多维分数就是一维分数一项一项加上去。这就是 HBOS 唯一的、也是最强的一个假设 —— 特征独立（feature independence）。

HBOS
=
Σi=1..d −log₂( ρi + α )

d 是特征数；ρi 是第 i 维上、该点所在格子的密度

这个假设换来的是指数级的省：要数清二维的联合分布，15 个格子就得 15×15 = 225 个格子，10 维就是 15¹⁰ ≈ 5.8×10¹¹ 个格子 —— 根本数不过来。而 HBOS 只要 15×10 = 150 个格子。它用「假装独立」把指数复杂度换成了线性。

这个假设究竟丢掉了什么？看一张图

把本页 220 个点画成 8×8 的网格（左边是真实的二维计数），再把两个边缘直方图相乘、画成右边的「独立假设眼中的世界」。

左：只有对角两个团有人（左上、右下是空的）　/　右：四个角都被认为「有人」，因为每个角上，x 和 y 各自都很常见

那两个空角落，就是全部问题的开始。右上角的坐标是「x 落在右团、y 落在左团」—— 现实中一次都没出现过；但 HBOS 只会分别检查「x 常不常见」（常见）和「y 常不常见」（常见），于是判定：一切正常。

它的盲区：组合异常

两维各自都很正常，组合起来却从未出现过 ——
HBOS 对此完全无感。

6

和邻居们比一比

HBOS 不是「更好的 KNN」，它是另一个极端：用「独立假设」换了速度，代价是看不见变量之间的关系。

算法核心问题复杂度最怕什么
HBOS你所在的格子挤不挤？O(n·d)变量之间有组合 / 相关结构
KNN离第 k 个邻居多远？O(n²·d)密度反差大的数据
LOF比邻居稀疏多少倍？O(n²·d)多密度簇、边界点
COF连不连得上？O(n²·d)稀疏但连贯的结构
IForest几刀能把你切出来？O(n log n · t)局部密度差异
HBOS 赢的地方

高维、大数据、要快

百万行、上百列也能单机跑完；结果可加、可逐维拆解（每一维贡献多少分一目了然），非常好向业务解释「为什么它被标红」。

HBOS 输的地方

组合异常、强相关特征

本页第 4 节就是活例子。另外如果两列高度相关（比如「身高 cm」和「身高 m」），同一件事会被算两遍，分数被无端放大。

实践里常见的组合是：HBOS 粗筛 → 局部方法（LOF/COF）或集成模型复核。两者的盲区不重叠，正好互补。

7

什么时候用 · 要小心什么

适合

大规模粗筛

无论多少维都能线性扫完，是「第一道闸门」的好人选。

适合

本身就是离散的特征

类别、等级、次数这类天然分档的变量，直方图就是它的原生表示，不用额外处理。

小心

n_bins 的选择

常用 10–20。太少会把异常抹平（一格吞掉整个真空区），太多则每格样本太少、分数抖动。样本量的经验法则：每格至少要有十几个点。

小心

强相关特征

独立假设会被重复计数。要么先做相关性筛选 / PCA，要么就用能建模联合分布的方法。

小心

长尾分布

等宽分箱对偏态数据很不友好：绝大多数点挤在头几个格子里，长尾那一侧一个点占一格。先做 log 变换，或改等频分箱。

小心

分数不能跨数据集比

−log 密度的量纲依赖特征单位（换成「米」分数就变了）。它只在同一份数据内部有意义，用来排序和取分位数。

工程提示：PyOD 里有现成的 HBOS(n_bins=10, alpha=0.1, tol=0.5, contamination=0.1)。把 n_bins 设成 "auto" 会用 Birgé–Rozenblac 规则自动定每维的最优格子数。

展开：公式、伪代码与 PyOD 实现对照

0 · 术语对照

缩写 / 记号英文全称 · 中文
HBOSHistogram-based Outlier Score · 基于直方图的异常分
histhistogram density · 直方图密度，即每格的 ρ
n_binsnumber of bins · 每维切几格
α (alpha)regularizer · 稳定剂，防止 log(0)
toltolerance · 容差，决定落在训练范围外的样本怎么处理
P9595th percentile · 正常点分数的 95 分位，常拿它当判定线

1 · 定义

HBOS(p) = Σᵢ₌₁ᵈ log( 1 / histᵢ(pᵢ) ) = − Σᵢ₌₁ᵈ log( histᵢ(pᵢ) )

论文用自然对数；PyOD 用 log2，并在密度上加 α：

HBOS_pyod(p) = − Σᵢ₌₁ᵈ log₂( histᵢ(pᵢ) + α ), α = 0.1 by default

换底只差一个常数因子，排序完全等价；加 α 会略微改变排序（把「空」和「极空」压成同一档），这是工程上的取舍。分数越大越异常。

2 · 直方图怎么建（和 numpy 对齐）

对第 i 维，取训练集上的 min、max，等分成 n_bins 段，边界 edges；每格的密度是

hist[k] = count[k] / (n · width), width = (max − min) / n_bins

也就是 np.histogram(x, bins=n_bins, density=True)，满足 Σₖ hist[k]·width = 1。取格子下标用 np.digitize(v, edges, right=True) − 1：落在最右边界上的值归最后一格。

3 · 落在训练范围之外怎么办（tol）

情况PyOD 的处理
比最小边界还小，但差距 ≤ width·tol算进第 1 格
比最大边界还大，但差距 ≤ width·tol算进最后 1 格
差得更远取该维最低的 log 值（等价于最异常的那一档）

tol 默认 0.5，即「差半格以内算边界格，差得更多就当成最异常」。这也是为什么测试集里出现远超训练范围的极端值时，HBOS 会给它一个很高的分。

4 · 伪代码

# fit
for i in range(d):                       # 每一维独立处理
    edges[i], hist[i] = histogram(X[:, i], n_bins)   # density=True

# score
for p in X:
    s = 0
    for i in range(d):
        k = digitize(p[i], edges[i]) - 1              # 找到格子
        s += -log2(hist[i][k] + alpha)                # 该维贡献
    score[p] = s           # 论文里再取负号统一成「越大越异常」

注意：没有循环里套循环。这就是 O(n·d) 的全部来源。

5 · PyOD 源码里的对应（3.6.x）

hist[:, i], bin_edges[:, i] = np.histogram(X[:, i], bins=n_bins, density=True)

bin_inds    = np.digitize(X[:, i], bin_edges[:, i], right=True)
out_score_i = np.log2(hist[:, i] + alpha)      # 注意：这里还没有取负
...                                            # 越界处理（见第 3 节）
self.decision_scores_ = invert_order(np.sum(outlier_scores, axis=1))

invert_order 就是取负号，所以最终 decision_scores_ 越大越异常，和其它 PyOD 模型保持一致。n_bins="auto" 时改用 get_optimal_n_bins()（Birgé–Rozenblac 规则），让每一维自己决定格子数。

6 · 复杂度与出处

建直方图 O(n·d)；打分 O(n·d)；内存 O(d·n_bins + n)。没有距离矩阵，所以能吃到很大的数据。原论文也给了「动态分箱」（等频）的变体，PyOD 默认用等宽。

M. Goldstein, A. Dengel, Histogram-based Outlier Score (HBOS): A Fast Unsupervised Anomaly Detection Algorithm, KI-2012（35th German Conference on AI, Poster & Demo Track）, 2012。

三句话带走

  1. HBOS 不问「你离别人多远」，只问「你所在的格子挤不挤」。
  2. 做法：每维切格子、数人头得密度 → 取 −log → 各维直接相加。快到不需要距离矩阵。
  3. 代价是假设各维独立：两维都正常、组合起来从未出现过的点，它看不出来 —— 切多细都看不出来。
