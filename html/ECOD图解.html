你排在第几名？

ECOD（Empirical Cumulative Distribution-based Outlier Detection，基于经验累积分布的异常检测）。它大概是所有异常检测里最省事的一个：不量距离、不切格子、不选参数，把每一维从小到大排一次队，排在队头或队尾的人最可疑。这篇用大白话和两个能动手的演示讲清它 —— 也包括它那个结构性的盲区。

一句话先说清

把每一维从小到大排队，排在队头或队尾就越可疑；
多维就把各维的「稀罕程度」直接相加。

名字里的 Empirical Cumulative Distribution（经验累积分布）听着吓人，其实就是排队点名：220 个数排好队，你排第 k 名，就意味着「不超过你的比例是 k/220」。它不拟合任何分布曲线、不算密度，只看名次。所以它一个参数都不用调。

排中间

「前后都站满了人」

排第 110 名（220 人）左右，说明「你这样的值遍地都是」，一点都不可疑。

排两端

「一头几乎没人」

排第 2 名或第 219 名，说明「这么极端的值很稀有」，第一个被叫出去。

记住这个画面：ECOD 眼里没有「距离」，只有「名次」；而且每一维都只看自己，从不看「谁和谁一起出现」—— 这个盲区在第 4 节等着我们。
1

先说好处：快，而且零参数

老办法要算 n² 次距离；ECOD 每维排一次序，之后人人查名次。

KNN、LOF、COF 的第一步都是「谁离谁多远」，n 个点要两两比一遍；即便绕开距离，很多办法也得先决定「格子切多粗」之类的旋钮。ECOD 一个旋钮都没有：每维排序一次（O(n log n)），之后每个点只需在排好序的数组里二分查一下名次 —— 没有迭代、没有分布假设、没有格子数。偏态、双峰、长尾都不影响「名次」的公平性，因为名次只跟顺序有关，跟数值的形状无关。

同样 12 个点：左边是 66 条线，右边是一条队伍；点再多，右边也只是排序 + 查表

工程上怎么用：零参数让它成为最省心的第一道粗筛 —— 先用 ECOD 把 99% 明显正常的数据刷掉，剩下的再交给 LOF / 集成模型细看。每一维贡献多少分还能拆开看，向业务解释「为什么它被标红」只要一句话：「它在收入这一维排进了前 2%」。
2

第 1 步：一维排队 → 尾部概率

排第 k 名 = 不超过你的占 k/n；越靠两端，这个比例越小。

这个「不超过你的比例」就是经验累积分布（ECDF）：队头那格的值 ≈ 0（几乎没人比它更小），队尾那格的值 = 1。把比例反过来用：比例越小的那一侧越稀罕。分数就用一句话换算：

单维得分
=
−ln( 尾部概率 )

尾部概率 = 左侧（不超过你）和右侧（不小于你）两个比例中更小的那个；比例 50% → 0.69 分，10% → 2.3 分，1% → 4.6 分

为什么偏偏是 −ln？两个理由

理由一

「越稀有越可疑」要有尺度

尾部概率从 10% 掉到 1% 是「稀有 10 倍」。−ln 把它翻译成「多了 2.3 分」，正好可以用加法讨论「稀有 10 倍 + 稀有 10 倍」。

理由二

相乘变相加

多维时各维的尾部概率本来要连乘（独立假设下）；取 ln 之后变成相加。相加就能一眼看出「这次是 x 维拉高的分，还是 y 维」。

分数上不封顶：它对「多稀有」给多高的分，不做任何封顶 —— 名次最靠边的正常点自动成为「最稀罕」的参照。220 个点里排第 1 名，就是实打实的 −ln(1/220) ≈ 5.4 分。

和正态分布是什么关系？—— 它是 Z-Score 的「无参数版」

你多半听过更老的招数 Z-Score：假设数据服从正态分布，先估出均值 μ 和标准差 σ，把位置换算成「离均值几个标准差」（z），再查正态曲线表得到尾部概率，概率小就报警。注意它的后半段和 ECOD 完全一样：尾部概率小 → 可疑 → 取 −ln。差别只在中间那一步 —— 概率从哪儿来：

Z-Score（正态 3σ 法则）

位置 → 假设正态 → 查表

「你离均值 2.4 个 σ」→ 到正态曲线表上查这一侧的尾部概率。整条命脉押在一个前提上：数据真是正态的。像「收入」这种长尾数据，少数巨富会把 σ 撑大，查表反而给巨富打出偏低的分。

ECOD（本篇主角）

位置 → 查自己的队伍

「不超过你的占 k/220」—— 排名比例直接就是尾部概率的实测值（随机抓一个人，不超过你的概率正是这个比例；队伍越长估得越准）。分布什么形状都行，表都不用查。

所以正态分布在 ECOD 里扮演的角色是一个被换掉的零件：数据越接近正态，两种方法的分数越贴近。下表用本页真实数据对照（x 维，都取更稀罕的一侧）：

x 的位置Z-Score：正态查表 −ln PECOD：排名实测 −ln P差在哪
0（正中间）0.690.75几乎重合
±1.6（靠边）2.902.91 / 3.20很接近
±2.4（两端）4.805.39排名是台阶（第 1 名就是 1/220），且数据非严格正态

反过来，数据不正态时两者分道扬镳，这正是 ECOD 存在的理由：长尾、双峰、厚尾，正态表一概失效，而排名永远可用。另外对接近正态的数据，正态查表值的主导项是 z²/2 —— 也就是说「离均值越远，分数按平方上涨」；ECOD 继承了这条直觉，却不需要数据真是正态。

一句话：ECOD 原封不动地继承了 Z-Score 的分数语言（尾部概率、−ln、多维相加），只把「查正态曲线」这个危险零件换成「查自己的队伍」—— 数据越正态，它越像 Z-Score；数据越不正态，它越占便宜。

第 2 步：两头都看，取更稀罕的一侧；多维相加

队头和队尾各算一次，谁更稀罕听谁的；
多维直接相加。

极小和极大都是异常，所以每一维算两个尾部概率（左侧、右侧），取 −ln 之后取大者作为这一维的贡献；d 维加起来就是总分。这背后是「各维独立」的假设 —— 边缘名次拼不出联合名次。

ECOD
=
Σi=1..d max( −ln El(xi), −ln Er(xi) )

El / Er 是第 i 维上「不超过 / 不小于该值」的经验比例；取两侧中更稀罕的一侧

这个假设换来的是指数级的省：要数清二维的联合名次，联合分布的「格子」数量随维数爆炸；而 ECOD 每维只要一次排序，加多少维都是线性代价。它用「假装独立」把指数复杂度换成了线性的。

它的盲区：组合异常

每一维都只是「稍微靠边」，加起来却够不着判定线。

考察点是 4 个 (±1.6, ∓1.6) 型的组合点：x、y 单独看都还在正常点的常见区间（约 P4~P96），但按云的主轴 y ≈ 0.5x 衡量，它们斜着偏出约 2.5~3σ。下表用 pyod 同款的「单点打分」协议逐个算（分母见严谨版第 5 节）：

注意这个对比：一头极极端，一个人就值 6 分 —— y = 2.8 的右侧尾部概率只有 0.2%，−ln 直接给 6.09 分，加上另一维的 0.75 就越线了。而考察点两维各偏 4~7%，「稀有 20 倍 + 稀有 15 倍」加起来，居然比不上「稀有 500 倍」的一维。因为尾部概率是每维自己算自己的，「x 大 y 小要搭配出现」这条信息在两根投影轴上根本不存在。

连「拧旋钮」的机会都没有

不少方法还能靠调参数挣扎一下。ECOD 是零参数的：PyOD 里只有 contamination，而它只影响「报几个」的阈值，完全不改变分数本身。名次里从来没有「两维怎么搭配」这条信息 —— 所以这不是「参数没调好」，而是结构性的盲区，任何设置都救不回来。

和一个正常点的差距有多小？正常点分数最高 8.59（它有一维确实排到了极边上）、P95 = 6.31；考察点 5.87。它们不是「差一点被抓住」，而是被 5% 的正常点稳稳压住 —— 比 95% 的正常点还「正常」。

和邻居们比一比

ECOD 不是「更好的 KNN」，它是另一个极端：用「独立假设 + 只看名次」换了速度和零参数，代价是看不见变量之间的关系。

算法核心问题复杂度要调的参数最怕什么
ECOD这一维你排第几名？O(n log n · d)无组合 / 相关结构；分布谷底
HBOS（直方图方法，下一篇的主角）你所在的格子挤不挤？O(n·d)n_bins变量之间有组合 / 相关结构
KNN离第 k 个邻居多远？O(n²·d)k密度反差大的数据
LOF比邻居稀疏多少倍？O(n²·d)k多密度簇、边界点
COF连不连得上？O(n²·d)k稀疏但连贯的结构
IForest几刀能把你切出来？O(n log n · t)树数 / 子采样局部密度差异
ECOD 赢的地方

零参数、可解释、不怕分布形状

没有格子数、没有 k、没有树深 —— 拿来就用。偏态、双峰、长尾都不影响名次的公平。百万行、上百列也能单机秒出，每一维的贡献还能拆开向业务解释。

ECOD 输的地方

组合异常、相关特征、双峰谷底

本页第 4 节就是活例子。另外它只看名次：如果正常数据是两个分开的团，落在两团之间谷底的点在每一维都排中间 → 分数很低 → 漏报（这个 HBOS 反而抓得住：空格子封顶高分）。

两个零成本模型正好互补：双峰分布的谷底，HBOS 抓得住（空格子给封顶高分）、ECOD 看不见；偏态长尾，ECOD 稳（名次不看形状）、HBOS 的等宽分箱会被拉爆。实践里常见的组合是 ECOD / HBOS 各跑一遍粗筛 → 并集送进局部方法（LOF/COF）复核，两家的盲区不重叠。
7

什么时候用 · 要小心什么

适合

零参数基线第一名

拿到一份新数据，先跑 ECOD：不用调任何东西，30 秒拿到一张可疑名单和一条可解释的分数线。

适合

分布形状奇怪的维度

收入、耗时这类长尾特征，Z-Score 会被均值方差带偏，ECOD 只看名次，天然免疫。

适合

大规模 + 高维粗筛

每维一次排序，加维只是线性加价；百万行 × 上百列也能单机跑完，还支持并行。

小心

分数依赖样本量 n

−ln(尾部概率) 的分母是 n：同样的位置，220 个点和 220 万个点算出的分数不同。它只在同一份数据内部有意义（排序、取分位）。

小心

重复值多的离散特征

大量并列名次会让 ECDF 出现平局（并列的人共享同一个比例），分数区分度下降；纯类别变量要先编码或换方法。

小心

组合异常 & 分布谷底

两维各自常见、组合从未出现 → 看不见（第 4 节）；双峰分布的谷底 → 也看不见（第 6 节）。要用能看「联合」或「局部」的方法复核。

工程提示：PyOD 里就是 ECOD(contamination=0.05) —— 没有其他超参数。contamination 只决定「按分数报前多少比例」，不影响分数本身；fit 一次之后 decision_function 可以随时给新点打分。

0 · 术语对照

缩写 / 记号英文全称 · 中文
ECODEmpirical Cumulative Distribution-based Outlier Detection · 基于经验累积分布的异常检测
ECDFempirical cumulative distribution function · 经验累积分布：E(v) = #{x ≤ v} / n
U_l / U_rleft / right tail score · 左尾 / 右尾得分，各为 −ln(尾部比例)
skewness偏度的符号，用于选择重点看哪一侧的尾部

1 · 定义

E_n(v) = #{ x ≤ v } / n （经验累积分布）
U_l(p) = −ln E_n(p) （左尾：越小越异常） U_r(p) = −ln E_n(−p) （右尾：越大越异常） O_i(p) = max( U_l, U_r ) （第 i 维取更稀罕的一侧） ECOD(p) = Σᵢ₌₁ᵈ O_i(p) （逐维相加，越大越异常）

论文与 PyOD 都用自然对数；尾部比例用 ECDF 直接估计，不做任何分布假设。分数越大越异常。

2 · ECDF 怎么建（平局的处理）

对第 i 维，把 n 个值升序排序，按位置给概率 1/n, 2/n, …, 1；相等的值共享组内最大的概率，即并列名次都按「不超过该值的个数 / n」计 —— 与 statsmodels 的 ECDF 一致。所以 E(v) 恰好是 #{x ≤ v}/n，不会因为排序顺序不同而变化。

3 · 偏度修正（PyOD 源码里的玄机）

skewness = sign( skew(X) ) （先取符号：+1 / −1 / 0） U_skew = −U_l · sign(sk−1) + U_r · sign(sk+1) （源码原式） sk = +1（右偏）→ U_skew = U_r sk = −1（左偏）→ U_skew = U_l sk = 0（对称）→ U_skew = U_l + U_r O_i = max( U_l, U_r, U_skew )

对任何偏度非零的列，U_skew 都不会超过 max(U_l, U_r)，所以最终等价于每维取左右尾中更稀罕的一侧。只有偏度恰好为 0 的列（实践中几乎只在常量列出现）才退化为两头相加。本页数据两维偏度 0.06 / −0.15，全部走 max 分支。

        c_le = count_le(sorted_col[i], p[i])     # #{x ≤ p[i]}，二分查找
        c_ge = count_ge(sorted_col[i], p[i])     # #{x ≥ p[i]}，二分查找
        s += max(-log(c_le/n), -log(c_ge/n))     # 该维贡献
    score[p] = s

注意：没有循环里套循环，也没有任何迭代优化。这就是它快且稳的全部来源。

5 · PyOD 源码里的对应（3.6.x）

self.U_l    = -1 * np.log(column_ecdf(X))        # 左尾得分
self.U_r    = -1 * np.log(column_ecdf(-X))       # 右尾得分（取负后排序）
skewness    = np.sign(skew(X, axis=0))
self.U_skew = self.U_l * -1 * np.sign(skewness - 1) + self.U_r * np.sign(skewness + 1)
self.O      = np.maximum(self.U_skew, np.maximum(self.U_l, self.U_r))
decision_scores_ = self.O.sum(axis=1)            # 逐维相加

column_ecdf 用「排序 + 平局取组内最大概率」实现第 2 节的 ECDF。还有一个容易踩的细节：给新点打分时，源码会把训练集拼接在新点前面再算 ECDF —— 分母是 2n+1（训练集算两遍、新点算一遍），而不是 n。本页交互面板用的正是这个「单点协议」，与 decision_function([q]) 逐位一致；正常点的 P95 则用训练集自己的协议（分母 n），两者只差在尾部略有出入，不影响任何结论。

6 · 复杂度与出处

fit 每维一次排序 O(n log n · d)；打分每维两次二分 O(log n · d)；内存 O(n·d) 存排序结果。没有距离矩阵、没有迭代，可分布式扩展。ECOD 是 COPOD 的改进版（同一批作者，去掉了 copula 修正），PyOD 官方推荐用 ECOD 而不是 COPOD。

Z. Li, Y. Zhao, X. Hu, N. Botta, C. Ionescu, G. H. Chen, ECOD: Unsupervised Outlier Detection Using Empirical Cumulative Distribution Functions, IEEE Transactions on Knowledge and Data Engineering, 35(12): 12181–12193, 2022。

7 · 本页数字是怎么来的

数据与《1.PYOD.原理主线版》notebook 的 ECOD 一节完全相同（band 云：y = 0.5x + 0.866ε，220 点，相关系数 0.577；考察点 (1.6, −1.6)、(−1.6, 1.6)、(1.5, −1.4)、(−1.4, 1.5)）。页面加载时用上面的公式实时重算，得到正常点 P95 = 6.308、考察点（单点协议）5.866 / 5.663 / 5.121 / 5.169，与 notebook 里 PyOD 的输出逐位一致 —— 也就是说这套 JS 实现和 pyod.models.ECOD 在这个数据上完全等价。notebook 打印的批量协议值（4 个考察点一起打分）为 5.813 / 5.619 / 4.980 / 5.024，0% 越过 P95。

三句话带走

  1. ECOD 不量距离、也不切格子，只把每一维排队问名次。
  2. 分数 = 每维「左右两头中更稀罕一侧」的 −ln 尾部概率逐维相加；排序一次，之后人人线性查表。
  3. 代价同样是假设各维独立：两维都常见、组合从未出现过的点，它看不见 —— 而且它零参数、没有旋钮，这个盲区是结构性的。
