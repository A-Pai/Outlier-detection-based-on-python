簇不是球，是一条弯带：距离要顺着数据形状走

LOF 假设正常区域是「各向同性的团」，用直线距离找邻居。可当正常数据躺在一条弯曲的带子上，直线会抄近道跨过弯折——明明沿着带子走了很远还算正常，却被当成低密度。COF 把「直线距离」换成「沿数据形状走的距离」。

01

破口：LOF 的直线距离错在哪

主线定位

主线定位：正常 = 沿链式方向可达；分数 = 链式密度比；本节破口 = 仍是 O(n²) → 2.4 由 CBLOF 补。

LOF 用欧氏距离定义邻域，背后藏着一个没说出口的假设：正常区域是各向同性的团——往哪个方向走都一样。可真实数据常是流形：轨迹、工艺曲线、螺旋、弯带。沿带子方向走出很远，其实仍是正常。

图 1 · 弯带上的 A、B：直线很近，但沿数据形状走很远——这就是 LOF 失真的地方

📌 一句话差别：LOF 用「直线距离」量密度，COF 用「顺着数据形状走的距离」量密度。带子弯曲处，两者分道扬镳；球状团里，两者几乎一致。
02

三步：把近邻图上的「走法」换成链式距离

Chandola et al., 2009

COF 不是新分数，而是把 LOF 里的「距离」换掉，其余密度比框架照搬。

① 建图欧氏距离找 k 近邻 → 邻接图 和 LOF 一样，先用直线找邻居
② 链式距离从 x 出发，每次走最近的未访问点，累加边长 = SBN 路径 沿数据流形走的实际长度
③ 密度比COF(x) ∝ 邻居的平均链式密度 ÷ x 的链式密度 思路与 LOF 相同，距离换了度量

图 2 · 链式（最短路径）距离：一圈一圈沿着带子走，而非跨空白抄近道

  • ① 邻接图先用欧氏 k 近邻把点连成图——注意「找邻居」这步仍是直线，链式只发生在「量距离」这步。
  • ② SBN 路径Shortest-path Based on Neighborhood：从 x 出发，每次贪心走到最近的未访问邻居，把边长累加起来。带子上的点因此沿带子被串起来。
  • ③ 链式密度用链式距离替代欧氏距离，算可达距离与局部密度，再取「邻居平均密度 ÷ 我的密度」——比值越大于 1，越异常。
📌 实现要点：PyOD 的 COF decision_function 是对传入集合内部找近邻算分，不是对照训练集打分。只传一两个点会 IndexError——见复现节的 joint=True 处理。
03

怎么读 COF 分数：≈ 1 是正常

比值，无单位

和 LOF 一样，COF 是密度比：分子是邻居平均链式密度，分母是我的链式密度。

图 3 · 三类点：密集团与链中段 COF 都 ≈1，只有离群的孤点被抬高

COF 值含义典型场景
≈ 1我的链式密度与邻居相当 → 正常密集团内部、弯带上的点
≫ 1我明显比邻居稀（沿形状也孤） → 异常远离流形的孤点
< 1我比邻居还密通常仍判正常
💡 关键对照：链中段的点绝对密度低（周围点少），但 COF 仍判正常——因为沿带子方向它们是连续的。这正是 LOF 与 COF 的分水岭。

05

破口与边界：COF 也不是万能的

通向 2.4 CBLOF

COF 补上了「球状假设」，代价是更重的计算与更脆的实现。

  • O(n²) 且更慢每个点都要维护最短路径，是本章最慢的算法；上万样本请先降采样，或改用同为聚类视角但复杂度更低的 CBLOF。
  • 仍是直线找邻居建图那一步仍用欧氏 k 近邻——若流形本身断裂或噪声太大，邻接图先错，后面全错。
  • 打分实现的坑PyOD 的 COF decision_function 对传入集合内部算分；集合点数 ≤ n_neighbors 会直接 IndexError。
  • 高维同样失效链式距离依赖近邻结构，维度灾难下近邻失真，跳 Ⅲ 族或先降维。
⚠️ 和 Ⅱ 族所有成员一样，必须先标准化再算距离，否则量纲大的那一维会独占「近邻」的定义。

复现

与 notebook 一致

本页图形与分数来自 1.PYOD.原理主线版.ipynb §2.3 的专属数据（确定性构造、无随机数）。核心两行：

# --- COF · 专属数据实验（与 LOF 同场对照）---
from pyod.models.cof import COF

m = COF(n_neighbors=15)
m.fit(X)
scores = m.decision_scores_          # 对整批训练集合打分
diagnose(m, 'COF', 'COF', scale=True, plot=True, joint=True)  # joint 避开 IndexError

判分规则：不比 AUC，只看考察点有没有排到正常点 P95 之上。实测 LOF 密团/链中段 1.018/1.047，COF 0.998/0.998；COF 主实验 P95=1.206，孤点=2.980。

💡 joint=True 是 COF / SOD 专用的对照技巧：把考察点并入整批一起打分再拆开，绕开「集合点数不足」的实现限制。
